# ESP32-S31-Function-CoreBoard-1 (Linux)

Espressif's ESP32-S31-Function-CoreBoard-1 (DigiKey `1965-ESP32-S31-FUNCTION-COREBOARD-1-ND`):
the ESP32-S31, two RV32IMAC harts with M/S/U modes and Sv32, 16 MiB in-package PSRAM, 16 MiB NOR
flash and a UART console. sbc-emu runs **Espressif's official Linux flash image, unmodified,
through the chip's own boot chain**:

```
mask ROM (esp-rom-elfs 20260528) -> U-Boot SPL (HP RAM) -> OpenSBI 1.6 (M) -> U-Boot 2024.07 (S)
  -> Linux 6.18 xipImage, executing in place from flash at 0x40400000 -> cramfs root from flash
```

No emulator-specific kernel, device tree, firmware stub or SBI: the ROM is Espressif's ROM ELF,
and everything after it comes from `s31_full_flash.bin` as `esptool write-flash 0x0` would write it.

## Running

```sh
scripts/esp32s31-fixture.sh              # Docker: build the image into cache/esp32s31/ (~1 h first time)
cargo run -p esp32s31 --release --example s31_linux -- \
    cache/esp32s31/esp32s31_rev0_rom.elf cache/esp32s31/images/s31_full_flash.bin \
    5500000000 scripts/esp32s31-shell.txt
```

UART0 goes to stdout. The optional script is esp-soc's (`waituart0`, `uart0 TEXT`, ...).
`S31_TRACE=1` prints hart 0's privilege and `satp` changes; `S31_REBOOTS=N` allows N reboots.

## What works (2026-11-18)

| | Evidence |
|---|---|
| ROM → SPL → OpenSBI → U-Boot → Linux | `ESP-ROM:esp32s31-20251218`, `U-Boot SPL 2024.07`, `OpenSBI: ESP32-S31 firmware active`, U-Boot autoboot, `Booting Linux on hartid 0`; root shell at 3.5 s of emulated time (~6 s wall on an M-series Mac) |
| Root shell over UART0, input and output | `scripts/esp32s31-shell.txt`: `uname -a` → `Linux esp32s31 6.18.0 #1 SMP ... riscv32 GNU/Linux`; `/proc/device-tree/model` → `Espressif ESP32-S31 (minimal)` |
| Two harts | OpenSBI HSM starts hart 1 through the ROM; `smp: Brought up 1 node, 2 CPUs`; systimer interrupts and IPIs on both CPUs in `/proc/interrupts` |
| Timer | systimer clocksource + per-CPU clockevent (16 MHz) through INTMTX and the CLIC's S-mode sources; `sleep 1` sleeps |
| Memory | 16 MiB PSRAM at 0x50000000 (`MemTotal: 14404 kB`), XIP text in flash, Sv32 with 4 MiB megapages |
| Reboot | `scripts/esp32s31-reboot.txt`: `reboot` → OpenSBI SRST → HP core software reset → `rst:0xc (SW_CPU_RESET)` → second boot to a shell |

## In the browser

The demo site's [ESP32-S31 page](https://joakimeriksson.github.io/sbc-emu/board.html?b=esp32s31) runs the same machine in the WebAssembly build (`sbc_boot_s31`): Espressif's mask ROM ELF and the official flash image, through the whole chain to the root shell on UART0, which the page's terminal is. It runs the core's JIT to WebAssembly (`riscv-rv32/src/jit.rs`): `node tools/wasm-smoke-s31.mjs` reaches `~ #` after 7.6 s on an M-series Mac (10.1 s with `SBC_JIT=0`), then `uname`, the device-tree model, both harts in `/proc/cpuinfo` and `sleep 1` all work. Input typed before Linux has enabled UART0 is held until it has.

The site serves the ROM from Espressif's esp-rom-elfs release (Apache 2.0) and the flash image from this repository's `esp32s31-linux-1` release (gzip'd, 5.9 MB), since building it takes an hour; `web/sources.html` lists the exact sources it was built from (the pins in `scripts/esp32s31-fixture.sh`).

## What does not work yet

- **Ethernet**: the DWMAC and MDIO probe, but no YT8531 PHY is modelled (`probe ... failed with error -16`).
- **SD/MMC**: no DesignWare MMC host model (`Timeout resetting block`).
- USB OTG, I²C devices, GPIO users, Wi-Fi: register models from esp32sim exist for some, none is
  claimed for Linux.
- Not in the `sbc-emu` CLI yet: the native runner is the `s31_linux` example.
- Speed: ~0.6× real time. The RV32 core runs decoded blocks in every mode (in S and U a block
  keeps to one virtual page and is taken only while its first instruction still translates to
  the physical address it was built from, `riscv-rv32/src/block.rs`) and compiles hot code in
  regions to AArch64 natively and to WebAssembly in the browser (`riscv-rv32/src/jit.rs`,
  `RV32_JIT=0` turns it off); PSRAM accesses translate once per MMU page. The documented boot's
  console transcript and final state are byte-identical to the interpreter's throughout: to the
  shell 22.9 s → 5.9 s natively. Generated code is now ~1% of a native profile: most of the
  time goes to the SoC's device models, ticked every 64-step quantum while Linux idles.

## How it is built

- `riscv-rv32/`: esp32sim's RV32 core, extended for the S31 Linux profile (`Cpu::privileged`,
  set by `new_esp32s31`): M/S/U, `medeleg`/`mideleg`, `sret`, `sfence.vma`, Sv32 (`mmu.rs`,
  hardware A/D update, a 256-entry TLB), `mcounteren`/`scounteren`, the `time` CSR (CPU clock,
  320 MHz as the device trees' `timebase-frequency`), illegal-instruction traps for CSRs the S31
  lacks (OpenSBI's feature probing depends on them), and the S31's CLIC-mode `scause`
  (SPP/SPIE aliases, SPIL reloaded by an interrupt-type `sret`, 64-byte `stvec`). The C3, C6 and
  P4 profiles are unchanged.
- `espressif/`: esp32sim's S31 SoC (`esp32s31`, `esp-soc`, `esp-periph` and their 32-bit
  `emu-core`) from esp32sim `d043ff1d` (MIT, `espressif/LICENSE`): mask-ROM boot, MSPI flash and
  PSRAM, the cache MMU, clocks, PMU, interrupt matrix, CLIC, systimer, UART. Changes for Linux:
  CLIC S-mode sources and the S apertures at 0x10a00000/0x10a10000; MPLL calibration without the
  IDF-only analog-master gate; OpenSBI's plain `HPCORE0_SW_RESET` trigger; the board preset
  `BoardInputs::function_coreboard_1` (16 MiB PSRAM whose MR2 reports 16 MiB to the SPL).

Requirements were taken from Espressif's sources at: OpenSBI `5395e03` (integration/v1.6-esp32s31),
U-Boot `e5dff8d` (integration/v2024.07-esp32s31), Linux `1962979` (integration/v6.18-esp32s31),
esp-buildroot-external `d75370b`, esp-linux-bsp `a427cfb`, Buildroot 2025.02.20.
